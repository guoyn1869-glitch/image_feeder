# 图递 / ImageRelay

[English version: README.en.md](README.en.md)

把一个本地图片注册进 Operit 的对话，让模型真正看见画面。

**版本：** 1.0.2 · **包 ID：** `com.operit.image_feeder` · **名称：** 图递 / ImageRelay

---

## 它解决什么问题

在聊天里发一个文件路径，模型是看不见图的。聊天后端能带上图片*引用*，但模型要真正拿到像素，必须由宿主的原生层把这张图注册进当前对话的图片池。

这个包只做这一步。别的什么都不做。

## 它和那些 vision 插件不是一路货

搜 "MCP vision" 会撞出一堆项目：`mcp-vision-server`、`llm-vision-mcp`、`vision-mcp-server`、`Visual-Enhancement-mcp`……名字都叫 vision，口号都是"让 AI 看见图片"。

**它们走的全是代理路线，本包走的是注入路线。这是两件不同的事。**

**代理路线**（那些项目）：

```
路径 → 读盘 → base64 → 发给另一个视觉模型 → 返回一段文字描述 → 交给主模型
```

主模型拿到的不是图，是别人对这张图的转述。

**注入路线**（本包）：

```
路径 → 注册进对话图片池 → 返回 <link type="image" id="..."> → 主模型看到原始像素
```

没有中间人，主模型看的就是这张图本身。

### 差在哪

| | 代理 | 注入（本包） |
|---|---|---|
| 模型收到什么 | 一段文字描述 | 原始图片 |
| 信息 | 有损，缺失不可逆 | 无损 |
| 二次追问 | 重新调一次 | 同一张图随便问 |
| 额外依赖 | 另一个视觉 API、另一份 key | 无 |
| 主模型要求 | 纯文本模型也行 | 必须多模态 |
| 宿主要求 | 普通工具即可 | 必须原生支持注册进图片池 |

简单说：代理是**把图讲给模型听**，注入是**把图递给模型看**。

### 为什么别人不做注入

不是没想到，是做不成。代理路线挂在 MCP 工具层就能跑；注入路线必须由宿主自己开这个口子——工具返回的 image content block，很多客户端会静默丢掉（GitHub Copilot CLI、OpenAI Codex 都有对应 issue）。

本包能做，是因为 Operit 的原生层提供了注册接口，并且这个包用的就是那条通道——跟用户手动上传图片走的是同一套渲染路径。

> 相关背景：Operit2 上有个 issue（`AAswordman/Operit2#319`）记录过这个问题，提出者试了四条替代路径都没通，指出插件想主动读图必须宿主原生支持。那个 issue 至今 Open。本包就是走通这条路的一个实现。

## 它不做什么

不含图库、不含分类、不含搜索、不含 OCR、不含图片处理、不含格式转换、不含发送。

想要能浏览、能搜索的图库，那是另一个包。这个包是 `路径 → 图片池 → 模型看见` 这条通路的最小实现。

## 安装

把本目录放进 Operit 的 `toolpkg` 位置安装，或者直接装 Release 里附带的 `.toolpkg`。

如果报 `already exists`，先卸载旧版的 `com.operit.image_feeder`。Operit 遇到重复的 `toolpkg_id` 是直接拒绝，不会覆盖。

装好之后，`feed_image` 和 `check_image` 两个工具对模型可用。

---

## 接口速查

### `feed_image`

把一张图注册进当前对话的图片池。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | string | 是 | 绝对路径（`/sdcard/...`）或 `file://` 开头。**`content://` 宿主不接受。** |
| `_debug` | boolean | 否 | 返回诊断用的 `debug` 块。 |

只有图片真正进了池子，才返回 `ok:true`。任何失败都返回 `ok:false`，并用 `error` 说明原因，附带 `note` 提醒模型不许凭猜测描述画面。

### `check_image`

轻量预检：路径存不存在、是不是文件、扩展名像不像图片。在花掉一次原生调用之前先探个路，不注册、不进池。

---

## 两件最容易踩的事

**`ok:true` 的意思是“进了池子”，不是“模型看见了”。**

模型能不能描述这张图，还取决于模型自己有没有视觉能力、以及图片有没有活到发出去的那一步。这个包只保证注册这一步。

**`content://` 用不了。**

宿主直接拒绝。得用真实的文件路径。如果你的来源是 content provider，先把它解析成文件系统路径再传。

---

## 装完之后怎么验

Operit 的内部实现不是公开契约，宿主升级有可能在没有任何提示的情况下把这个注册调用弄失效。所以每次宿主升级后，跑一遍这个检查：

1. 找一张真图，内容你自己心里有数。
2. 用 `_debug: true` 调 `feed_image`。
3. 确认 `ok:true`，并且 `debug.build` 是 `v1.0.2-selfreport`。
4. 问模型一个只有看见图才答得出的问题。

如果第 3 步返回 `ok:false` 并带 `api_missing`，说明宿主已经不再提供这个包依赖的接口了。
